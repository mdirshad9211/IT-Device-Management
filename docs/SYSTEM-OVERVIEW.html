0. How to use this document (read first)

Follow A → B → C the first time. Later jump any endpoint from the left nav.

A — Start the stack

npm install
cp .env.example .env
npm run docker:up
npm run prisma:migrate:deploy
npm run seed
npm run dev

curl http://localhost:4000/health

Expect "db":"ok" and "redis":"ok". Redis is required for notifications and the lifecycle job.

C — Recommended first-time walkthrough

  1. GET /health — confirm db/redis
  2. POST /api/v1/auth/login as super.admin — copy token
  3. GET /api/v1/clients — see seeded sites
  4. POST /api/v1/clients — create a site; copy id
  5. PATCH /clients/:id/location — location history
  6. POST /api/v1/devices — allot laptop; copy device id
  7. GET /devices/:id — see QR + assignment
  8. PATCH /devices/:id — change cpu/ram
  9. GET /audit-logs?entityType=Device&entityId=... — see fieldChanges
  10. Create OND → PATCH .../link → re-GET device → linkedOtherNetworkDevices
  11. Agent poll with storage 82% → check GET /notifications
  12. POST .../lifecycle with DISCARD
  13. Repeat allot with EMPLOYEE token → expect 403 FORBIDDEN

Each API section below documents: method/path, auth, roles, body, real success JSON, errors, and side effects.

1. System flow

HTTP → Routes + RBAC (401/403)
    → Controller → Service → Prisma
    → DomainEventBus (AuditableEvent)
         ├─ AuditListener → AuditLog (before/after/fieldChanges)
         └─ NotificationListener → BullMQ → SMTP worker

Modules never import another module’s repository. Cross-module work = events only.

POST /api/v1/devices/:id/assignments

POSTJWTDevice edit

Closes current assignment; creates new current row. Device id + QR unchanged. Body = same assignment object as allotment.

POST /api/v1/devices/:id/lifecycle

POSTJWTDevice edit

Body

{ "eventType": "DISCARD" }

eventType: DISCARD | REACTIVATE | MANUAL_DELETE | RETIRE | SCRAP.
MANUAL_DELETE = SUPER_ADMIN / DGN_IT_MANAGER only (SERVICE_MANAGER → 403).

Success 200 (DISCARD)

{
  "status": "DISCARDED",
  "discardedAt": "2026-08-20T15:30:00.000Z",
  "deletionDueAt": "2026-11-18T15:30:00.000Z",
  "retiredFlag": false
}

deletionDueAt = now + 90 days. Sweep warns ~15 days before; hard-deletes after due.

POST /api/v1/qr/:deviceId/run-poll

POSTJWTDevice edit

Emits agent.poll.requested. Returns { deviceId, agentId, requestedAt }.

One QR per device: service ConflictError + DB QrCode.deviceId @unique (P2002 if bypassed).

13. Background jobs

Daily 03:00 UTC (lifecycle-sweep):

  1. Hard-delete DISCARDED past deletionDueAt (emit device.deleted first for Audit).
  2. Warn devices ~15 days out once (discardWarningSentAt idempotency).
